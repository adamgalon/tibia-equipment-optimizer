# Data sources and feasibility

**Audit date:** 2026-10-12  
**Verified and revised:** 2026-10-13 — claims re-checked against the live sources; findings 2 and 4 corrected, findings 6 and 7 added.  
This is a technical feasibility review, not a legal opinion. It records what the published sources say today; re-check API documentation, terms, and licenses before a public data import or deployment.

## Findings

1. **There is no one-stop official equipment data feed in the sources reviewed.** TibiaData describes itself as a JSON API for information from Tibia.com. Its current v4 OpenAPI specification lists characters, worlds, creatures, spells, news, and related resources, but no item catalog, equipment, or market-price route. The published character schema includes fields such as level, vocation, and world, but not equipped items or skills. A public character lookup can help prefill basic profile information; users still need to enter their current equipment and usually their skills. The highscores route exposes skill values, but only for characters ranked high enough on their world (TibiaData runs highscores in restriction mode), so it can prefill skills for some users at best. Verified 2026-10-13 against spec version v4.10.0. Sources: [TibiaData API overview](https://docs.tibiadata.com/), [v4 OpenAPI specification](https://docs.tibiadata.com/swagger.json).

2. **TibiaWiki can fill part of the item and hunt-data gap, with licensing and coverage conditions.** An existing community API, [TibiaWikiApi](https://github.com/benjaminkomen/TibiaWikiApi), says it reads TibiaWiki/Fandom and exposes item and hunting-place resources. Its README says the API code is MIT-licensed; that does not license the underlying wiki content. The wiki's own MediaWiki API is also directly reachable (`https://tibia.fandom.com/api.php`, checked 2026-10-13), and its site info reports the content license as CC-BY-SA, linking to [Fandom licensing](https://www.fandom.com/licensing). Item pages use a structured `Infobox Object` template with fields such as `itemid`, `slot`, `levelrequired`, `vocrequired`, `imbueslots`, `upgradeclass`, `armor`, `resist`, and `attrib`, so items can be imported from wikitext without scraping HTML. Preserve source attribution and per-page license information, and confirm the exact license version for any imported/redistributed content. Do not assume that CipSoft-owned graphics or other game assets are covered by the wiki license. Sources: [TibiaWikiApi README](https://github.com/benjaminkomen/TibiaWikiApi), [TibiaWiki site info (license)](https://tibia.fandom.com/api.php?action=query&meta=siteinfo&siprop=rightsinfo), [example item: Falcon Plate](https://tibia.fandom.com/wiki/Falcon_Plate), [CipSoft video and screenshot policy](https://www.cipsoft.com/en/video-policy).

3. **Monk is a coverage gap for hunt recommendations.** The TibiaWikiApi documentation states that its hunting-place recommendation columns cover Knight, Paladin, and Mage, and that TibiaWiki has not added Monk columns. The same project parses Monk support from spell entries. This is useful coverage, but not enough to derive a Monk hunt recommendation. Confirmed 2026-10-13 in the wiki itself: `Template:Infobox Hunt` only has `lvl`/`sk`/`def` fields for knights, paladins, and mages. Sources: [TibiaWikiApi README](https://github.com/benjaminkomen/TibiaWikiApi#resources), [Template:Infobox Hunt](https://tibia.fandom.com/wiki/Template:Infobox_Hunt).

4. **No official price feed exists, but a public community price API does — with a sourcing risk.** *(Corrected 2026-10-13; the original audit said prices were not sourceable.)* TibiaData has no market or item-price endpoint, and no official CipSoft feed was found. However, [Tibia Market](https://api.tibiamarket.top/docs) publishes an unauthenticated API with per-world current market values (`/market_values`), price history (`/item_history`), item metadata, and world data. A test call on 2026-10-13 returned Antica data observed about six days earlier (e.g. Falcon Plate: sell offer ~31.4M gp, 30-day average sale ~30.9M gp). **Risk:** its open-source collector ([tibia-market-tracker](https://github.com/Marilyth/tibia-market-tracker), also cloned locally in the Codex workspace) logs a real character into the official client and drives it with simulated "human-like" mouse movement, client memory reads, and a network proxy. That very likely falls under [Tibia Rule 3b](https://www.tibia.com/support/?subtopic=tibiarules) ("Using Unofficial Software to Play"), so the feed can disappear without notice and its provenance is ethically grey. No terms of use or rate limits for the API were found. Phase 07 should keep manual prices and CSV import as the baseline; the community API may be an optional, clearly labelled third-party source behind an adapter. All quotes must be labelled by world, quote type, source, and timestamp.

5. **Official mechanics change, so data must be versioned.** CipSoft announced the fifth vocation Monk (news #8318, 2025-03-31) and released it on 2025-04-08, then published Monk balance adjustments on 2026-09-01 (news #8944). Rules and builds therefore need a source date or game revision. Sources: [Fifth Vocation release announcement](https://www.tibia.com/news/?id=8318&subtopic=newsarchive), [Monk Adjustments](https://www.tibia.com/news/?id=8944&subtopic=newsarchive).

6. **An equipped item's power depends on more than its base stats.** *(Added 2026-10-13.)* Any equipment recommendation must account for:
   - **Weapon Proficiency** (Summer Update 2025): a character unlocks up to seven perk levels per weapon by killing creatures with it. Summer Update 2026 lets two default perks be replaced. Balance patches also change specific weapons' perks (the 2026-09-01 Monk patch changes the Amber Kusarigama's tier 3 and 5 perks). The best weapon for a character therefore depends on their progress with each weapon, which no public API exposes, so the user must enter it.
   - **Exaltation Forge tiers:** upgradable weapons, armors, helmets, legs, and boots have a classification of 1–4 (wiki `upgradeclass`, market API metadata `tier`) that caps the forge tier at 1, 2, 3, or 10. Each tier adds a slot-specific effect (Onslaught, Ruse, Momentum, Transcendence, Amplification). Classification is a catalog fact; the actual tier is a per-copy user input.
   - **Imbuements:** the main source of elemental protection and life/mana leech; the number of slots (`imbueslots`) is a catalog fact, the chosen imbuements are user input.
   - **Current best-in-slot gear:** Summer Update 2026 (15.30, 2026-07-13) added the Moonsilver helmets and weapons, plus crafted Stellar Moonsilver weapons. Tibia "sets" on the wiki are item groupings; no set bonuses were found, so items can be scored per slot.

   Sources: [Weapon Proficiency](https://tibia.fandom.com/wiki/Weapon_Proficiency), [Equipment Upgrade](https://tibia.fandom.com/wiki/Equipment_Upgrade), [Summer Update 2026](https://tibia.fandom.com/wiki/Updates/Summer_Update_2026), [Moonsilver Set](https://tibia.fandom.com/wiki/Moonsilver_Set).

7. **Wiki items and market prices share one item ID.** *(Added 2026-10-13.)* The wiki `itemid` is the same ID the community price API uses: Falcon Plate is `28719` in both, and the API's metadata maps it back to the wiki name. This is the join key between catalog facts and prices, and the catalog should use it as the primary item identifier. Not yet verified: whether the price API tracks forged (tiered) copies separately from tier 0.

## Data-handling requirements

- For every imported value retain: entity and field, source name, source URL, source revision or fetch identifier, retrieved/observed timestamp, license label, attribution text or link, validation status, and confidence.
- Keep upstream/source facts separate from app calculations. A calculated score must link back to the exact inputs and version used.
- Keep historical snapshots instead of overwriting item stats or prices. Mark changed, stale, disputed, and missing data; never treat “not listed” as zero.
- Validate every source payload against a versioned schema before it changes the current catalog. Keep the prior snapshot if a source is unavailable or malformed.
- Use only official published information and permitted APIs. The initial plan does not include client memory reads, packet interception, or market scraping, and the project must not run a client-automation collector such as tibia-market-tracker itself.
- Preserve enough attribution in the UI and an About/Data Sources page to satisfy the chosen source license. If the exact license or rights are unclear, exclude that content from a public build until clarified.

## Open questions before Phase 02

- Confirm current Fandom terms, robots/API rules, and the exact per-page CC BY-SA license version before importing content at scale.
- Confirm whether the user wants to pursue a supported-fansite relationship or ask CipSoft/TibiaData for written data-use clarification before public or monetized deployment.
- Decide the minimum Monk hunt profile fields and how users may supply empirical hunt assumptions.
- Decide whether CSV/manual prices are sufficient for the first release, or whether to add the Tibia Market community API as an optional source given its collection method. If yes, ask its maintainer about terms of use and check how tiered items are priced.
- Decide which per-character inputs the builder collects: forge tier per item, imbuements, and Weapon Proficiency level/perks per weapon.
- Verify the hosting provider's scheduled-job support and database cost only after the stack proposal is approved.
